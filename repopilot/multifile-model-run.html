Auditable agent-to-verification path

  1. Issue retrieval: RepoPilot fetched synthetic public GitHub issue #3 rather than substituting a hardcoded repair request.
  2. Guarded source inspection: It preinspected both required Python modules and used only bounded read/search tools. The model also attempted an unavailable test read, which was safely bounded.
  3. Fresh model proposal: After six model turns, final-patch mode produced changed source for both approved paths. A prewritten reference source patch was not used as the model proposal.
  4. Static review: The proposed source was subjected to patch and static review. Review status was review_required, not auto-approved.
  5. Docker tests: The test runner observed baseline 0, expected reproduction failure 1, and passing patched suite 0. The workflow rejected any run with verified=false.
  6. Evidence retained: GitHub Actions uploaded result.json and the generated model-patch.diff for independent inspection.
Provenance and limitation. This was a curated synthetic multi-file issue with prewritten reproduction tests. The source patch was model-generated; the reproduction tests were not. A successful synthetic issue does not establish autonomous performance on arbitrary software or an official SWE-bench score. Any draft pull request requires human review.
