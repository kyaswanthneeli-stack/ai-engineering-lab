# RepoPilot v1.0.0 — Evidence-first AI coding agent (portfolio release)

**Release date:** November 19, 2026  
**Status:** Working, reproducible engineering prototype and portfolio demonstration; **not** production-autonomous software maintenance.

RepoPilot reads Python repository issues, chooses bounded read-only source inspections, uses a configured language model to propose a change, rejects uninspected or malformed edits, and offers a restricted Docker verification pipeline with explicit human control over pull requests.

## Included in v1.0.0

- Python package with an issue-to-patch command-line interface, issue-aware AST/source inspection, source/path checks, structured LLM output validation, bounded recovery/retries, and optional local Ollama or trusted OpenAI-compatible endpoint.
- Restricted Docker regression runner with baseline, failing reproduction, and patched-suite evidence on the supported controlled fixtures.
- Working GitHub issue to patch and approval-gated pull-request workflow. The Qwen2.5-Coder 7B two-file invoice candidate generated by the model was subsequently corrected during review for direct subtotal validation and merged as [PR #10](https://github.com/kyaswanthneeli-stack/ai-engineering-lab/pull/10). Do **not** present the corrected end-state as wholly AI-generated.
- The agent reliability and malformed-output recovery tests merged as [PR #12](https://github.com/kyaswanthneeli-stack/ai-engineering-lab/pull/12).
- An interactive [public recruiter demo](https://kyaswanthneeli-stack.github.io/ai-engineering-lab/repopilot/recruiter-demo.html) and [benchmark status page](https://kyaswanthneeli-stack.github.io/ai-engineering-lab/repopilot/benchmark-status.html).

A pinned cohort of **12** official SWE-bench Lite issues was attempted with local Qwen2.5-Coder 3B. The model produced **six** candidate patches; six other attempts timed out without a valid submission. The **official SWE-bench harness evaluated all six** submitted patches:

## Try it locally

Requires Python 3.11+; Docker is required for restricted verification. Model proposal requires a model provider such as local Ollama (no paid API is required if using Ollama).

```bash
git clone https://github.com/kyaswanthneeli-stack/ai-engineering-lab.git
cd ai-engineering-lab/repopilot
python -m pip install -e .
python -m unittest discover -s tests -v

# Re-run the deterministic fixture verification in a disposable Docker environment:
docker pull python:3.12-alpine
python -m repopilot.cli verify fixtures/calculator-buggy examples/issue.json \
  --output .runs/verification-v1.json
python -m repopilot.cli dashboard .runs/verification-v1.json \
  --output .runs/dashboard-v1.html
```

The fixture verification is a **reference-patch demonstration**, not a fresh LLM result. See [README.md](README.md) for real model configuration and the separate pinned-clone workflow.

## Limitations and safety boundaries

- Best suited to Python repositories and controlled demonstration cases. The model cannot be assumed to solve arbitrary issues, write correct tests, or work on every repository.
- Docker network/process/resource controls are defense in depth, **not** a hardened untrusted-code security boundary; use disposable workers without sensitive credentials.
- Generated proposals require review. No unattended production deployment or automatic code merging.
- This release does not claim 12/12 benchmark success, lower costs, measured commercial performance, or production-grade autonomous reliability.
- Open [recruiter walkthrough](recruiter-demo.html) for the actual model and Docker evidence.

**Forward plan:** v2 work on a **separate** development branch, aiming for better large-repository context, stronger test generation, safer retries, and more officially scored tasks. None of those features are claimed as completed in v1.
