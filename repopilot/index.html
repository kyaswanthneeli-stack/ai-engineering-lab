Engineering evidence, not promises.

A Python issue-to-patch harness with structured LLM proposals, safe patch validation, network-restricted Docker test execution, reviewable reports and explicit human approval for draft PR creation.

Architecture in one glance

GitHub issue→AST context→LLM proposal→Diff validator→Docker tests→Evidence / Human review

Bounded AI integration

Uses an OpenAI-compatible completion endpoint, JSON schema checks and a narrow Python-only patch policy.

Restricted execution

Container CPU, memory, process count and network limits. It is defense-in-depth—not a guarantee of isolation against malicious code.

Transparent evaluation

Benchmark reporting separates known-fixture verification from truly model-generated attempts and reports missing results as missing.

Reproduce the verified sample

git clone https://github.com/kyaswanthneeli-stack/ai-engineering-lab.git
cd ai-engineering-lab/repopilot
python -m pip install -e .
python -m unittest discover -s tests -v
docker pull python:3.12-alpine
python -m repopilot.cli verify examples/calculator examples/issue.json --output .runs/verified.json
python -m repopilot.cli dashboard .runs/verified.json --output .runs/dashboard.html

The sample uses a human-supplied reference patch. It proves the verification pipeline, not autonomous problem-solving. The offline dashboard is generated from the run evidence and can be opened in a browser.

Evaluation status

No SWE-bench resolution percentage, average token savings or cost-per-issue is claimed. The benchmark runner is prepared for traceable results; meaningful public numbers require a configured model and independently evaluated issue attempts.

Built as an inspectable engineering project

Repository and test artifacts are public. Model provider credentials and untrusted issue code must never be included in a hosted browser demo.
