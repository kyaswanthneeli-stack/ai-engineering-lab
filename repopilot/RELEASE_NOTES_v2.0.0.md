# RepoPilot v2.0 — Evidence-backed portfolio release notes

**Date:** November 20, 2026  
**Status:** Code and benchmark evidence verified in GitHub Actions. This document is a release-note handoff; **a formal GitHub Releases entry and version tag have not yet been created**. RepoPilot remains a portfolio-quality research prototype, not an unattended production code-repair service.

## What ships in the verified v2.0 code snapshot

- **Bounded source inspection:** guarded read-only repository file listing, keyword search and line-window inspection; limited tool steps and model context.
- **Model-generated repair proposals:** JSON/patch validation, source-edit checks and fallbacks for invalid proposals; Python AST-assisted context.
- **Iterative verification and recovery:** baseline tests, issue reproduction and patched regression in a restricted Docker environment; rejection of repeated failed source-patch candidates even if proposed tests change.
- **Provider reliability controls:** explicit native localhost Ollama mode; configurable per-request timeouts (10–120 seconds) and optional agent-step wall-clock budget (10–3600 seconds).
- **Evidence integrity:** signed-off per-task statuses, refusal to overwrite a completed batch directory, portable official-results parsing, prediction provenance checks and patch SHA-256 regression guards.
- **Manual official benchmark:** a 12-task SWE-bench Lite workflow runs only by explicit `workflow_dispatch`, avoiding surprise multi-hour model runs on normal pushes.
- **Human approval:** source changes and draft pull requests are subject to review; the tool does not automatically merge arbitrary generated changes.

## Boundaries and remaining work

- The tool is **Python-oriented and experimental**. It does not promise broad autonomous correctness.
- Passing local regression tests and restricted Docker checks are not sufficient to claim official SWE-bench success.
- Docker restrictions are defense-in-depth, **not** a hardened hostile-code sandbox.
- The tested workflows and authenticated GitHub integration rely on configuration and may fail on CPU-limited runners or large repositories.
- Human approval remains required before adopting or merging any proposed patch.
- The official 12-task result shows no improvement versus the original 1/6, 1/12 baseline; improving model solve rate is a future research goal.
- A formal immutable `v2.0.0` Git tag / GitHub Release entry is a **remaining publishing action**, not falsely represented as already complete.

**Claims suitable for a freelancer portfolio:** built and tested a Python LLM coding-agent proof of concept; integrated GitHub source inspection, model patches, Docker regression, human-approved PR workflow and an independent benchmark with transparent successes and failures.
